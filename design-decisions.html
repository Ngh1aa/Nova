P2.4 — product reasoning evidence

What I chose. What I rejected. What it cost.

Nova is not presented as a sequence of polished screens. This review surface makes the product decisions explicit: the alternative that was rejected, the trade-off accepted, the evidence used, and the uncertainty that still remains.

Decision standard

Evidence before certainty.

Each record distinguishes what is implemented and QA-verified from what is still untested with humans. The goal is not to claim every decision was right; it is to show how product judgment was made and bounded.

Seven decisions that shaped Nova

P24-D01 · Money model

Lead with Safe to spend, not raw balance.

The first question Nova answers is not “How much do I have?” but “What is actually safe to spend after near-term commitments?”

ImplementedLatest clarity pass not human-retested
See HomeResearch decision log

Chosen

Safe-to-spend hero + 14-day Money Horizon. Raw balance stays supporting context.

Rejected

  • Raw-balance hero
  • Interchangeable KPI dashboard
  • Unexplained financial-health score

Trade-off accepted

More explanation and horizon language in exchange for a model that supports a real spending decision.

Evidence

Current product thesis + active iOS 26 contract + Round 02 D-01 + post-Round-02 clarity implementation.

P24-D02 · Transfer guardrail

Agency with friction above Safe to spend.

A planning amount is not the same as the legal account balance, so Nova separates affordability guidance from actual balance validity.

Regression verifiedPrototype policy
See AmountSee Review

Chosen

Block above total balance. Above Safe to spend remains possible only after explicit plan-shortfall consequence + acknowledgement.

Rejected

  • Hard-block every amount above Safe to spend
  • Silently allow it with no consequence

Trade-off accepted

One extra decision step preserves user agency without turning the planning model into decoration.

Evidence

P0 transfer-integrity remediation plus product-integrity and transfer-impact browser regressions.

P24-D03 · Protected buffer

Protected means reserved unless the user changes the rule.

Correct arithmetic was not enough when the reserve behavior itself was still misunderstood.

ImplementedNot human-retested
Decision pointReview state

Chosen

State at the decision point: “Protected buffer stays reserved — this transfer does not use it.”

Rejected

  • Automatically consume the buffer
  • Hide the rule inside arithmetic

Trade-off accepted

A more conservative planning model in exchange for a stable meaning of “protected.”

Evidence

Round 02 D-03: 5/5 reached the transfer arithmetic, but only 1/5 correctly understood buffer behavior.

P24-D04 · Sensitive actions

Freeze and Report are different decisions.

The suspicious-payment experience favors consequence clarity over compressing high-risk actions into one control.

ImplementedNot human-retested
Transaction detailReport preview

Chosen

Separate Freeze and Report surfaces with distinct consequences and `DEMO ONLY · NO BANK CONTACT` beside the decision.

Rejected

  • Combined “Freeze / Report” action
  • Implied bank submission
  • Footer-only prototype disclaimer

Trade-off accepted

More UI and copy in exchange for less ambiguity at a high-consequence moment.

Evidence

Round 02 D-02 stayed mixed; the follow-up truth-boundary iteration is regression-protected.

P24-D05 · Failure recovery

Certainty about money movement comes before retry speed.

After authentication, network or revalidation failure, the user first needs to know whether anything happened to their money.

ImplementedNot human-retested
Biometric recoveryOffline recovery

Chosen

`NO MONEY MOVED` is dominant, the failure cause stays adjacent, balance is unchanged, and retry/passcode actions are secondary.

Rejected

  • Generic error + Retry first
  • Silent resend after reconnect
  • Ambiguous completion state

Trade-off accepted

Slightly slower recovery in exchange for stronger transaction-state certainty.

Evidence

Round 02 D-04 produced a negative cross-sectional self-report signal; recovery hierarchy was revised without claiming causality.

P24-D06 · Prototype scope

Smaller credible scope beats fake completeness.

The prototype only advertises recipient behavior it can actually preserve through the whole transfer journey.

Regression verifiedSaved recipients only
Choose recipientReceipt

Chosen

Saved recipients only, searchable, with selected identity persisted from selection through review, recovery and receipt.

Rejected

  • Nonfunctional “Add new recipient”
  • Silently default every transfer to Maya
  • Invent missing bank metadata

Trade-off accepted

Less feature breadth in exchange for a prototype whose visible capabilities are internally honest.

Evidence

P1.7 source correction + recipient-continuity regression deliberately verifies Daniel Lee through the flow.

P24-D07 · Art direction

Reset the visual contract instead of polishing the old theme.

When the warm-ledger direction made the product feel dated and too narrow on desktop, Nova treated it as an art-direction problem rather than a CSS detail.

Active contractRendered QA baseline
Current HomeCurrent system

Chosen

iOS 26 Financial Workspace: content-first, cool neutral, system type, restrained glass chrome, responsive desktop composition.

Rejected

  • Beige/paper-first ledger theme
  • Serif money UI
  • Generic SaaS sidebar
  • Narrow phone-like desktop column
  • Nested glass surfaces
  • Interchangeable dashboard-card grid

Trade-off accepted

Less decorative editorial novelty in exchange for platform familiarity, financial hierarchy and credible responsiveness.

Evidence

Active iOS 26 design contract + current project context + rendered/browser QA across representative evidence and product routes.

Evidence boundary

Supported claims

  • Each decision is traceable to a current contract, implementation, QA history or retained research evidence.
  • Round 02 changed priorities for D-01 through D-04.
  • The latest post-Round-02 changes are implemented and QA-verified.
  • The prototype intentionally chooses scope honesty over fake capability.

Not supported without new evidence

  • That every decision is objectively optimal.
  • That post-Round-02 comprehension improved.
  • Moderated task-success or time-on-task improvement.
  • User preference for the visual reset.
  • Conversion, retention, fraud reduction or production banking impact.
